# Security Policy

## Supported versions

Security-support commitments have not yet been established. No current version is guaranteed to receive security fixes on a particular schedule.

## Reporting vulnerabilities

Until the official security contact and GitHub Security Advisories are configured, **do not post exploit details, keys, credentials, or private logs in public issues**. Use private GitHub vulnerability reporting after the maintainer enables it. Maintainership should provide a monitored confidential contact channel before public launch.

## Scope

Reports involving Spectre ToolHub, installer, custom kernel integration, rootless Podman provisioning and guest display integration are relevant. Upstream problems in Debian, Kali, Podman, GNOME and Oracle VirtualBox should also be reported to the relevant upstream project.

## Disclaimer

Linux Spectre is not advertised as a fully hardened security boundary. Rootless containers reduce some privileges but do not guarantee complete isolation.
